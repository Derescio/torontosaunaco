# Policy Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the five policy pages on the new site from the extracted design content, and make "Schomberg (King Township)" read "Schomberg" in all extracted content.

**Architecture:** The extractor applies an approved copy-edit list to every page before writing, so `content/redesign/*.json` and `content/seo.json` carry the fix. A pure function turns a policy page's JSON into named parts; `PolicyPage` lays those parts out; `Blocks` renders individual content blocks and is reused by later Phase 2 pages. Five static pages in `app/(site)/` wire it together with `pageSeo()`.

**Tech Stack:** Next.js 15 App Router (JSX), Tailwind with tokens from `lib/site/tokens.js`, Jest + Testing Library (jsdom), Node ESM extractor in `scripts/extract-dc/`.

**Spec:** `docs/superpowers/specs/2026-11-26-policies-design.md`

## Global Constraints

- Copy comes verbatim from `content/redesign/Policy*.json`. Never retype copy in JSX. The only copy change is `"Schomberg (King Township)"` → `"Schomberg"`, made by the extractor.
- Title/meta/canonical/JSON-LD only via `pageSeo(route)` and `<JsonLd>`. No hand-written metadata.
- New components go in `components/site/`, never in `components/redesign/`. Phone/desktop switch is `desktop:` (998px). Never `md:`.
- Container: `mx-auto max-w-site px-5 desktop:px-8`. Tailwind tokens only; map the design's values to the nearest default Tailwind step or existing token (table in Task 3).
- No database access. No secrets in output. No `.env` writes.
- Tests sit beside the code as `*.test.js(x)` (`__tests__/` is git-ignored).
- Windows: write JS with Write/Edit (Git Bash strips backslashes); PowerShell 5.1 drops `--` before npm args; rerun a build that dies with 0xC0000409.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A policy JSON whose shape changes after a future re-extract (e.g. no "At a glance" box): `policyParts` must throw an error naming the file, so the build fails instead of shipping a half-rendered page. (Task 2 test)
2. Inline `tel:`/`mailto:` links inside paragraphs stay real, styled links. (Task 1 test)
3. The current policy tab is a non-link with `aria-current="page"`; the other four are links, in design order, on every page. (Task 3 test)
4. At 390px, the "At a glance" rows and tab pills wrap without horizontal scroll. (Task 5 browser check: `scrollWidth <= 390`)
5. A copy-edit rule that stops matching (the design changed) must fail `extract:dc` instead of silently doing nothing. (Task 0 test)

### Task 1: `Blocks` renderer

Inline links get `[&_a]:font-semibold [&_a]:text-ink [&_a]:underline hover:[&_a]:text-walnut`.

Section 1 = first `paragraph` intro, `text` glance label, `definitions`, then groups each starting at a `heading` level 3. Section 2 = `heading` level 2, `paragraph`, `link`s.
- Any missing piece throws `Error("policyParts: <page.file>: <what is missing>")`.
