# Blog Index and Article Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `/blog` (every Sanity post, newest first, design overrides for its 11) and restyled `/blog/[slug]` on the new site.

**Architecture:** `lib/site/blog.js` reads Sanity (read-only) and merges each post with the design's card for the same slug into one card shape. `SanityImage` resizes on Sanity's CDN. `PostCard`, `BlogIndex` and `BlogPost` render with existing site pieces (`SectionHeader`, `Split`, `Breadcrumb`, `CtaBand`, `SiteImage`). Both routes are static with ISR.

**Tech Stack:** Next.js 15 App Router (JSX), `@sanity/client`, `@sanity/image-url`, `@portabletext/react`, next/image, Jest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-26-blog-design.md`

## Global Constraints

- Sanity read-only via `client` from `lib/sanity.js`; tests mock it (no network in tests).
- Copy for the index from `content/redesign/Blog.json`; post titles and dates always from Sanity.
- `/blog` metadata/JSON-LD via `pageSeo("/blog")`. Article metadata built from Sanity with OpenGraph `type: "website"` (CLAUDE.md), canonical `https://www.thetorontosaunaco.com/blog/<slug>`, title suffix `| The Toronto Sauna Co.`.
- Images: design photos via `SiteImage`; Sanity photos via `SanityImage` (Sanity CDN resizes). No Vercel image transforms. `sizes` always.
- `revalidate = 7200` on both routes; `generateStaticParams` for articles. Guard all Sanity data (`Array.isArray`).
- New components in `components/site/`; `desktop:` breakpoint; tokens only.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Sanity down or empty at build/revalidate: `/blog` still renders the design's 11 cards, never an empty grid or a crash. (Task 1 + Task 3 tests)
2. A post with no `titleimage`, no `description`, or a missing `publishedAt`: its card renders without broken images or "Invalid Date". (Task 1 test)
3. Portable Text with external links, internal links, headings and inline images renders safely (`rel="noopener"` on external, images via Sanity CDN). (Task 4 test)
4. A design card whose slug isn't in Sanity any more: it's simply not shown (the list follows Sanity). (Task 1 test)
5. At 390px the 2-column card grid doesn't overflow. (Task 5 browser check)

### Task 1: `lib/site/blog.js`

**Files:** Create `lib/site/blog.js`, `lib/site/blog.test.js`.

**Interfaces (produced):**
- `DESIGN_CARDS: Map<slug, { category: string|null, summary: string, image: { src, alt } }>` from `Blog.json` cards (slug = last path segment of `href`; category = the date line's first part after dropping a leading "Latest", or null when the line is only a date).
- `formatDate(iso) -> string|null` — `"November 18, 2026"` (en-CA, `timeZone: "America/Toronto"`); null for missing/invalid.
- `toCard(post) -> { slug, href, title, date, category, summary, image }` where `image` is `{ kind: "design", src, alt } | { kind: "sanity", source, alt } | null`; summary = design summary, else Sanity `description`, else null.
- `getPosts() -> Promise<post[]>` (GROQ in the spec; returns `[]` on error or non-array, logging the error).
- `getPost(slug) -> Promise<post|null>` (adds `content`).
- `getCards() -> Promise<{ cards: card[], fromDesign: boolean }>` — `getPosts().map(toCard)`; when empty, the design's 11 cards in design order with their own date text (`fromDesign: true`).
- `relatedCards(cards, slug, n = 3) -> card[]` — first `n` cards whose slug ≠ `slug`.

  - `formatDate("2026-11-18T15:00:00Z") === "November 18, 2026"`; `formatDate(undefined) === null`; `formatDate("nope") === null`.
  - `toCard` for a covered slug: design category, summary and `image.kind === "design"`, Sanity title and date. For an uncovered slug with `titleimage` and `description`: `category === null`, summary = description, `image.kind === "sanity"`. Uncovered with neither: `summary === null`, `image === null`.
  - `getCards` with fetch → `[]`: 11 design cards, `fromDesign: true`; with fetch rejecting: same, no throw.
  - `getCards` with two posts: cards follow fetch order; a design slug absent from Sanity isn't added.
  - `relatedCards` skips the current slug and returns 3.

**Interfaces:**
- `sanityLoader({ src, width, quality }) -> src + "?w=<width>&q=<quality ?? 75>&auto=format&fit=max"` (append with `&` if `src` already has a query).
- `sanityDims(source) -> { width, height } | null` from `source.asset._ref` (`image-<id>-<w>x<h>-<ext>`).
- `SanityImage({ source, alt, sizes, fill, priority, className })` — url from `urlFor(source).url()` computed on the server side caller: **`PostCard`/pages pass `src` = `urlFor(source).url()` and dims**, so the client component gets only strings and numbers. - `PostCard({ card, featured = false, priority = false })` (server): photo (`SiteImage` for design, `SanityImage` for Sanity, a linen placeholder block for none) in a 3:2 `rounded-card` box; caps line `[category, date].filter(Boolean).join(" · ")` (featured prefixes "Latest"); title (`h2` featured / `h3` grid) linking to `card.href`; summary; "Read the article" link. Featured uses `Split imageSide="left"`.
