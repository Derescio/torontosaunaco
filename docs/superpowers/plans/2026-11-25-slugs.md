# Product Slugs and ID Redirects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Products and Accessories get design-route slugs. Today's product pages are served at the slug URLs, and
every ID URL 308s to its slug.

**Architecture:** `lib/products/slugs.js` holds the type → URL rule (`productPath`), and a server helper resolves a
route param into "render this product" or "redirect there". A shared mongoose plugin fills empty slugs on save. A
staging-only backfill CLI plans slugs from the price diff's design ↔ product matching and writes the missing ones.

**Tech Stack:** Next.js 15 App Router (JS), Mongoose, mongodb driver (CLI), Jest + babel-jest.

**Spec:** `docs/superpowers/specs/2026-11-25-slugs-design.md`

## Global Constraints

- Additive schema only: add `slug`, rename or remove nothing.
- Slug field: `{ type: String, unique: true, sparse: true, trim: true, lowercase: true }`.
- A slug is the route below its root: saunas `/saunas/`, `Cold Plunge` → `/cold-plunges/`, `Outdoor Shower` →
  `/outdoor-showers/`, `Hot Tub` → no URL (`null`). Indoor slugs keep `indoor/` (`indoor/pure-cube-552`).
- The backfill refuses any database but `staging`. `test` needs `--production` and is never run in this slice. It
  never prints `MONGO_URI` and never overwrites an existing slug.
- Redirects use `permanentRedirect` (308). A product with no slug, or a hot tub, renders as today (no redirect).
- Don't touch card/link components, `components/redesign/`, `redirect-map.csv`, `/signin`, `/orders` or `/hot-tub`.
- Domain `https://www.thetorontosaunaco.com`.

## Review Focus

- Mixed-case or trailing-slash slug params (`/cold-plunges/Arctic`): look up the lowercased param. Pinned in Task 5.
- A slug from the wrong family (`/cold-plunges/pure-cube-552`, `/saunas/arctic`) must 404, never render. Task 5.
- An ObjectId-shaped param with no product → 404 (no redirect loop). Task 5.
- `/saunas/indoor/<x>` where `<x>` is only an outdoor slug → 404. Task 5 (`resolveProductParam("indoor/x")`).
- Re-running `--apply` writes nothing, and a doc that already has a slug keeps it even if the design differs. Task 3.

### Task 5: Route resolution

**Files:**
- Create: `lib/products/resolve.js`, `lib/products/resolve.test.js`

**Interfaces:**
- Consumes: `kindOf`, `productPath`, `isLikelyMongoObjectId`, `connectDB`, `Products`.
- Produces: `resolveProductParam(param, kind) -> Promise<{ product } | { redirectTo } | null>` (`product` is plain JSON):
  - ObjectId: `findById`. If missing → `null`. If `productPath(p)` is set → `{ redirectTo }`. Otherwise `{ product }`
    (the legacy render, any type).
  - Otherwise: `findOne({ slug: param.toLowerCase() })`. Return `{ product }` only if `kindOf(p) === kind`, else `null`.
  - `staticSlugs(kind, { indoor }) -> Promise<string[]>`: slugs of that kind. For saunas: `indoor: true` gives only
    `indoor/…` slugs with the prefix removed; `indoor: false` excludes them.
